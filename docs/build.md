# Build Guide

This guide covers building the SwarmSAR workspace correctly, from a clean Ubuntu 26.04 install to a running simulation. For installing ROS 2 and Gazebo themselves, see [setup.md](setup.md).

## 1. Workspace Layout

ROS 2 requires a specific workspace structure. The repository must sit **inside** a `src/` folder of a workspace — it is not runnable from an arbitrary clone location.

```
~/ros2_ws/              <- the workspace (you create this)
├── src/
│   └── SwarmSAR/        <- this repository
│       ├── src/          <- the 9 ROS 2 packages (communication, navigation, ...)
│       ├── launch/
│       ├── worlds/
│       ├── models/
│       └── config/
├── build/                <- generated by colcon, not committed
├── install/              <- generated by colcon, not committed
└── log/                  <- generated by colcon, not committed
```

Note the two `src/`: the outer one is the ROS 2 workspace convention, the inner one is this repo's own source tree (see [../README.md](../README.md#project-structure)).

## 2. Clone Into the Workspace

```bash
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src
git clone <repo-url> SwarmSAR
```

## 3. Source ROS 2 Before Building

Every terminal you build or run from must have ROS 2 sourced first:

```bash
source /opt/ros/lyrical/setup.bash
```

If you added this to `~/.bashrc` during setup, new terminals do this automatically. Verify with:

```bash
echo $ROS_DISTRO
# Expected: lyrical
```

## 4. Build

From the **workspace root** (`~/ros2_ws`, not the repo folder):

```bash
cd ~/ros2_ws
colcon build --symlink-install
```

`--symlink-install` symlinks Python files instead of copying them, so edits to `.py` files take effect without rebuilding. You still need to rebuild when adding new files, changing `setup.py`/`package.xml`, or editing non-Python files (SDF, YAML, launch files are also symlinked, so those update live too).

### Build a single package

While iterating on one module, avoid rebuilding everything:

```bash
colcon build --symlink-install --packages-select navigation
```

### Clean rebuild

If the build is in a broken state (stale caches, renamed packages, dependency changes):

```bash
rm -rf build/ install/ log/
colcon build --symlink-install
```

## 5. Source the Install Space

After every build, source the workspace's own overlay (on top of the ROS 2 base):

```bash
source install/setup.bash
```

Add this to `~/.bashrc` once so it persists across terminals:

```bash
echo "source ~/ros2_ws/install/setup.bash" >> ~/.bashrc
```

**Order matters**: `/opt/ros/lyrical/setup.bash` must be sourced before `~/ros2_ws/install/setup.bash`.

## 6. Verify the Build

```bash
ros2 pkg list | grep -E "communication|navigation|formation|mapping|planning|search|battery|collision|simulator"
```

All 9 packages should be listed. If any are missing, check the corresponding `colcon build` output above for errors in that package's `package.xml` or `setup.py`.

## 7. Run

```bash
ros2 launch simulator single_drone.launch.py
```

## Common Build Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| `Package 'simulator' not found` | Workspace not sourced, or build didn't finish | Re-run `source install/setup.bash`; check `colcon build` for errors |
| `colcon: command not found` | `python3-colcon-common-extensions` not installed | `sudo apt install python3-colcon-common-extensions` |
| Build succeeds but `ros2 launch` can't find `worlds/earthquake_city.world` | `simulator/setup.py` data_files didn't pick up the file | Confirm the file exists in `worlds/` at the repo root, then `colcon build --packages-select simulator` |
| `E: Unable to locate package ros-lyrical-*` or `404 Not Found` during `apt install` | Ubuntu 26.04 / ROS 2 Lyrical mirrors not fully synced yet (very recent release) | Run `sudo apt update` again after a few days, or try a different mirror; see [setup.md](setup.md) |
| `Could not find a package configuration file ... ros_gz_sim` | `ros_gz` packages not installed | `sudo apt install ros-lyrical-ros-gz ros-lyrical-ros-gz-sim ros-lyrical-ros-gz-bridge ros-lyrical-ros-gz-interfaces` |
| Gazebo opens but errors on a `gz-sim-*-system` plugin | Plugin filename mismatch for this Gazebo Jetty point release | Check the exact error for the plugin name, cross-reference [gazebosim.org/docs/latest](https://gazebosim.org/docs/latest/) |
| Changes to a `.py` file have no effect | Built without `--symlink-install` | Rebuild with `colcon build --symlink-install` |

## Rebuilding After Common Changes

| You changed... | Command |
|-----------------|---------|
| A node's Python logic | Nothing, if built with `--symlink-install` |
| `setup.py` (new entry point / dependency) | `colcon build --packages-select <package>` |
| `package.xml` (new dependency) | `colcon build --packages-select <package>` |
| A new package added under `src/` | `colcon build` (full, so colcon discovers it) |
| `worlds/`, `models/`, or `config/` files | `colcon build --packages-select simulator` (unless already symlinked) |
